工作写作涉及大量与写作无关的机械苦差事：从粘贴的段落中去除多余的空格、检查字数限制、删除重复的名称列表、将某些内容转换为 URL slug。

这十七个工具就是用于这部分工作的。它们都在浏览器本地运行，这不是一个小细节——您粘贴的草稿通常是未发布的，您正在排序的列表通常是某人的个人数据。

衡量你所写的内容

字数统计听起来已经解决了，直到客户要求正好 800 个字，而您的编辑器说 820，或者表单拒绝您的 1,995 个字符的文本，并且没有解释换行符的位置。

  • 字计数器 — 标准度量。粘贴、阅读、调整。
  • Letter Counter — 计算字符和字母频率。当您调试为什么某个段落感觉不对时很有用：它通常是重复的字母模式，而不是梦想。

关于“一个单词”含义的注释：不同的计数器在连字符、数字和 URL 方面存在分歧。如果确切的数字很重要，请使用检查您工作的人员使用的同一柜台，并提前达成一致。这是一个真正常见的小而无意义的争论的根源。

清理你没有写的副本

您收到的大多数文本都略有损坏：复制粘贴产生的双空格、杂散的制表符、匆忙打字造成的大小写不一致。手动修复它速度慢且容易出错。

  • 文本修剪器 — 立即删除每一行的前导和尾随空格。这比此列表中的其他任何内容修复了更多的“格式看起来损坏”报告。
  • 文本大小写转换器 — 在块中的句子大小写、标题大小写、大小写之间切换。也是撤消意外的大写锁定段落的最快方法。
  • Text to Slug — 将标题变成干净的 URL slug。粘贴你的标题，得到标题，完成。

slug 生成器除了 URL 之外还有一个用途：它是一种快速生成可读文件名或锚点的方法，人们一眼就能解析，这比“final_final_v3”要好。

使用列表

列表、库存、邮件合并、标签清理、调查回复、电子表格列——在某些时候，一切都变成了列表，每个列表都需要排序、去重或随机化。

  • 重复行删除器 — 比较两个列表，或清理一个列表。输出会告诉您删除了多少重复项，这在您报告结果时非常有用。
  • List Sorter — 与结构化列表输入相同的工作。
  • List Randomizer — 随机排列抽签顺序、测验序列或围墙入围名单，这样就不会有人怀疑存在偏袒行为。
  • 行号添加器 — 编号行，供在票证或代码审查评论中参考。

这里的经典陷阱是一个看起来经过重复数据删除但实际上并非如此的列表：“Apple”、“apple”和“Apple.”对于计算机来说是三个不同的行。在重复数据删除之前，请修剪空格并去除尾随标点符号，否则您将不会合并任何内容并得出数据是干净的结论。

预览和格式化

Markdown 赢了，但情况并不统一。你的工具一半会渲染它，一半不会，而没有渲染的一半通常是高级人员必须粘贴到的工具。

  • Markdown Preview — 实时渲染，因此您可以在表格或嵌套列表到达客户端之前检查其实际外观。
  • Text Repeater — 重复字符串 N 次。对于生成填充、测试数据或偶尔在文档中表达观点很有用。

Markdown 预览是整个集合中安静地节省最多时间的工具，因为渲染文档中的损坏表格比原始文本中的损坏表格更明显，也更令人尴尬。

其余的，以及何时接触它们

  • 随机字符串生成器 — 生成可读的随机数、占位符 ID 或短代码。比手工发明一些东西更好，因为你不会意外地重复使用它。
  • [[摩尔斯电码|摩尔斯电码翻译器]] — 真正有趣，偶尔对主题项目或谜题有用。

这些是频率较低的工具，但它们无需花费任何费用即可添加书签，并且它们解决了“我现在需要一个看起来随机的值，但我不相信自己能够编出一个值”的具体问题。

真实的编辑过程

当草稿从其他人处到达并需要以您的名义发出时，可以使用以下顺序。

  • 1.修剪。 首先通过 Text Trimmer 运行整个文档。空白损坏隐藏在您永远看不到的段落内。
  • 2.干净的大小写。 仅对标题使用 文本大小写转换器。切勿将大小写转换应用于完整的草稿 - 它会破坏专有名词。
  • 3.测量。 在书​​写之前用 [[字计数器|字计数器]] 检查长度，这样您就知道该作品的形状。
  • 4.预览。 如果包含 Markdown，则使用 Markdown Preview 进行渲染。
  • 5. Slug. 最后从最终标题生成 URL slug，使用 Text to Slug — 之后更改标题会破坏该 slug。

整个过程需要几分钟，并且消除了文档技术上正确但明显错误的错误类别。

作家关于隐私的问题

我未发布的文本会离开我的计算机吗？ 不会。这些工具会在您的浏览器中处理文本，并且不会存储或传输任何内容。

有长度限制吗？ 没有服务器端限制，因为没有服务器调用。极大的输入受到您自己设备内存的限制。

我可以将输出用于商业用途吗？ 可以，自由使用，无需归属。

他们可以在电话上工作吗？ 是的。布局会调整，并且运行相同的代码。

这些工具不能为您做什么

值得直言其局限性，因为机械化错误事物的工具只会产生更快的错误。

这些实用程序都无法告诉您句子是否清晰，主张是否有来源，或者语气是否适合听众。他们计算字符数；他们不评判散文。在该页面上的每个指标上得分都很高的文本仍然无法阅读。

他们也不编辑。当您发现自己大规模地手动重写单个子句时，文本工具已经无法满足您的需求，您需要一个合适的编辑器、一个用正则表达式查找和替换的工具（Regex Tester 确实非常适合排练）或一个脚本。使用浏览器作为机械层，并对其之上的所有内容保留自己的判断。

他们不会做的另一件事是修复不良来源。如果您的电子表格充满了不一致的命名 - “Dr”、“DR”、“Dr.”全部集中在一列中 - 一个工具会对您忠实提供的内容进行排序和删除重复内容，并且您仍然会在应该有一个的地方保留三个条目。清理数据是一个决定，而不是一个机械步骤。首先确定规范形式，然后应用它，然后检查。

保持工作清单可用

如果你维护一个潜在客户、链接、参考文献或术语的列表，它就会悄然退化。失败模式总是相同的：看起来相同的条目实际上并不相同，并且一次合并不会删除任何内容。

有效的维护过程很无聊：修剪空白、标准化大写、去掉尾随标点符号，然后消除重复。按照这个顺序——去重后的修剪会丢失条目。每月在活动列表上执行一次此操作会将两小时无法恢复的混乱变成十分钟的苦差事。

当两个列表需要协调时（例如，登记列表与出勤列表）首先使用 List Sorter 对两个列表进行排序，使它们对齐，然后通过肉眼进行比较。在比较之前对双方进行排序是两分钟检查和二十分钟狩猎之间的区别。
