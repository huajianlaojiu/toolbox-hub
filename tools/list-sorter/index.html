About the List Sorter

The List Sorter alphabetises a list and gives you both directions at once, ascending and descending, so you can take whichever you need without running it twice. Sorting uses standard string ordering, which is case-sensitive, meaning capital letters sort before lowercase ones. That is the behaviour to know about when a list mixes cases and the result looks unexpected.

Where people use the List Sorter

  • Alphabetising a list of names or keywords before publishing it.
  • Ordering a set of filenames or tags for a review.
  • Finding the first and last entries in a long list quickly.
  • Checking whether an item is missing from an unordered list.

How to use the List Sorter

  2. 2

  3. 3

  4. 4

    Normalise case if the order looks wrong

    If your list mixes cases, convert it to one case first, since capitals sort before lowercase letters.

Tips and best practices

  • Lowercase the list first if mixed case gives a strange order.
  • Pad numbers to a fixed width when you need numeric rather than text order.
  • Remove duplicates before sorting if you want a clean unique list.

Frequently asked questions

Why do capital letters come first?

Because sorting compares character codes, and uppercase letters have lower codes than lowercase ones. Normalise the case first if you want a plain alphabetical order.

Does it sort numbers numerically?

No. Items are sorted as text, so 10 comes before 2. Pad numbers to a fixed width if you need numeric order.

Does it remove duplicates?

No. Every line is kept. Run the list through the Duplicate Line Remover first if you want the unique set.

Does it handle accented characters?

Yes, following the browser's locale rules, which usually place accented letters near their base letter.

Can I sort by line length instead?

No. The sort is alphabetical only.
