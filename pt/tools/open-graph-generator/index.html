About the

The Open Graph Generator builds the og tags that control how a page looks when its link is shared. It emits og:url, og:title, og:description and og:type from a single line of input, which is the minimum set most platforms read. Paste the result into the head of your page and the preview card stops being whatever the platform guessed.

Where people use the

  • Adding sharing tags to a page that currently has none.
  • Fixing a link preview that shows the wrong title or description.
  • Producing a consistent block across a set of landing pages.
  • Preparing tags for a launch before the page goes live.

How to use the

  1. 1

    Enter the three fields

    URL, title and description, separated by vertical bars, for example https://example.com | Page Title | A short description.

  2. 2

    Generate

    Four og tags are produced, including og:type set to website.

  3. 3

    Copy the block

    Paste the tags into the head of your page.

  4. 4

    Add an image tag separately

    og:image is not included, because it needs a full URL to a real file. Add it yourself pointing at an image that is publicly reachable.

Tips and best practices

  • Use absolute URLs; scrapers cannot resolve relative paths.
  • Add og:image yourself, at about 1200 by 630 pixels.
  • Re-scrape with the platform debugger after changing tags; previews are cached.

Frequently asked questions

Why does my shared link still look wrong?

Platforms cache previews aggressively. Once the tags are correct, force a re-scrape with the platform's own sharing debugger, or wait for the cache to expire.

Is og:image required?

Not strictly, but a link with no image gets a plain text card, which is far less likely to be clicked. Add one.

What size should the image be?

Around 1200 by 630 pixels is the common recommendation, because it survives cropping on most platforms.

Do I need Twitter-specific tags too?

Most platforms read the og tags. A card tag for Twitter can override the layout, but it is optional.

Can I use relative URLs?

No. og:image and og:url must be absolute, including the scheme, because an external scraper has no base URL to resolve against.
