URL Encoder/Decoder

URL encode decode

URL encode decode ブラウザ内でローカルに実行

About the

URL エンコーダは、テキストをパーセント エンコード形式に変換するため、URL に配置されても存続し、%E4%BD%A0%E5%A5%BD のようなものを見つめて、その内容を知りたいときに再度デコードします。スペース、アンパサンド、疑問符、非 ASCII 文字などの文字はすべて、URL 内で特別な意味を持っているため、これらを raw で渡すとリンクが切断されたり、さらに悪いことに、サーバーが受け取る内容が暗黙的に変更されたりすることがあります。エンコードでは、各安全でない文字がパーセント記号とその後に続く 2 つの 16 進数に置き換えられます。

Where people use the

  • スペースを含む値を使用して検索またはフィルター URL を構築します。
  • アドレスバーまたはログからコピーされたパーセントエンコードされた文字列を読み取ります。
  • クエリエンコーディングを必要とする API 呼び出しの値を準備します。
  • パラメータにアンパサンドを含むリンクが壊れた理由を確認しています。

How to use the

  1. 1

    方向を選択してください

    エンコードは、読み取り可能なテキストをパーセントエンコード形式に変換します。デコードすると元に戻ります。

  2. 2

    テキストを貼り付けます

    エンコードの場合は、クエリ文字列に入れたい値を貼り付けます。デコードするには、パーセントでエンコードされたフラグメント全体を貼り付けます。

  3. 3

    変換する

    結果はすぐに表示されます。デコードが失敗した場合、入力は有効なパーセント エンコード データではありませんでした。

  4. 4

    URLにコピーしてください

    エンコードされた値は、名前=値のペアとして疑問符の後にアンパサンドで結合されます。

ヒントとベストプラクティス

  • URL 全体ではなく、各パラメータ値を個別にエンコードします。
  • サーバー上で値が間違っていると思われる場合は、その値が 2 回エンコードされているかどうかを確認してください。
  • URL の場合は %20、フォーム本体の場合は %20 であることに注意してください。

よくある質問

スペースがプラス記号ではなく %20 になったのはなぜですか?

これは、最新の標準に従い、%20 を生成する encodeURIComponent を使用しているためです。スペースを意味するプラス記号は、一般的なパスやクエリ セグメントではなく、application/x-www-form-urlencoded 本文にのみ適用されるフォーム送信規則です。

文字列のデコードが失敗するのはなぜですか?

通常、パーセント記号の後に 2 桁の 16 進数ではないものが続くためです。これは、文字列が 2 回エンコードされた場合、または文字の途中で切り取られた場合に発生します。一度に 1 つのレイヤーをデコードします。

URL 全体を一度にエンコードしますか?

URL 全体ではなく、コンポーネントをエンコードします。完全な URL を渡すと、スラッシュ、コロン、疑問符もエンコードされ、ブラウザーで使用できなくなるものになります。代わりに個々のパラメータ値をエンコードしてください。

中国語や絵文字などの UTF-8 文字はどうなりますか?

これらは UTF-8 バイトとしてエンコードされるため、1 つの文字は数パーセントエスケープされた 3 つ組になります。それは正しく、UTF-8 を期待するすべてのサーバーはそれを適切に読み取ります。

スラッシュはエンコードされていますか?

はい、encodeURIComponent はスラッシュをエンコードします。これは意図的なものです。パラメータ値内のスラッシュをパス区切り文字と間違えてはなりません。
