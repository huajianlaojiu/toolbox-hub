## 〇、结论先行

**工程完成度很高，但钱的路径现在是断的。**

站点本体健康：Next.js 16 静态导出、1891 个页面全部生成成功、15 语言译文齐备、线上 200 可访问、SEO 基础设施（canonical / hreflang / sitemap / JSON-LD / 信任页）基本正确。这套「零后端、零数据库、零 API 成本」的架构是项目最大优势，不该破坏。

但存在三个硬事实：

1. **广告不会展示**：4 类页面的手动广告位全部写死 `data-ad-slot="auto"`，这不是合法广告单元 ID；项目文档又明确 Auto ads 要「过审后」才开。即使明天来 10 万流量，广告展示量仍是 0。
2. **合规层面有两处可能直接导致拒审/封号**：全站无条件加载 AdSense 却没有任何 CMP/同意管理，而隐私政策白纸黑字宣称「有同意通知」；同时「零上传、纯本地、文件不离开设备」的宣称与 AdSense 脚本、unpkg CDN、以及嵌入的 OpenReel 应用内多个第三方付费 API 明显冲突。
3. **无法衡量**：无 GA4、无 GSC 导出数据、无事件埋点、GitHub Pages 也不给站主访问日志。项目文档自己写了「没有这个数字，后面所有动作都是盲的」。

**一句话建议：下一步不是加工具、不是补翻译，而是「让广告真的能填 + 让合规不封号 + 装上数据眼睛」。** 这三件做完之前，其它投入的边际收益接近零。

### 1.2 一次 `git push origin master` 之后发生什么

| # | 步骤 | 关键事实 |
|---|---|---|
| 1 | 触发 | 仅 `push.master` + 手动触发，**无 paths 过滤**，改一个 md 也会跑全量 |
| 2 | `npm ci` | Node `22` 浮动小版本；`xlsx` 从 `cdn.sheetjs.com` tarball 安装 |
| 3 | 生成 sitemap | 第 1 次，写 `public/sitemap.xml`（1776 URL） |
| 4 | 翻译 | 当前**无** `GOOGLE_TRANSLATE_KEY` → 走 gtx 免密钥分支，**只跑 `--langs pl,vi`**（注释却写「8 语言」） |
| 5 | `npm run build` | `prebuild` **再**生成一次 sitemap（第 2 次，纯冗余）→ `next build` 导出 1891 页 |
| 6 | 回写 master | `git add src/i18n/messages src/i18n/content` → **漏了 `posts`** → commit `[skip ci]` → push |
| 7 | 清理 | `find out -name '__next*' -delete`（对非空目录不可靠，且**无断言**） |
| 8 | 校验 | 仅 `test -f` 三个文件存在，不校验内容/URL 数/译文覆盖率 |
| 9 | 发布 | peaceiris 把整个 `out/` 推到 `gh-pages` 分支，Pages 自动发布 |

- 回写不会无限循环：`[skip ci]` + GITHUB_TOKEN 推送不触发 + `git diff --cached --quiet` 幂等保护。但 workflow **无显式护栏**（无 actor 判断、无路径过滤）。
- 单次 CI 约 11–14 分钟；本地构建约 3.5–4 分钟（编译 48s + TS 23s + 1891 页 2.2min）。
- 线上最后一次部署是 **2026-10-27**，本地已有更新的构建（sitemap lastmod 2026-11-01），存在未上线产物。

### 1.3 一次页面访问发生什么

1. GitHub Pages 返回静态 HTML（每页 `<head>` **无条件**加载 `adsbygoogle.js`）。
2. `I18nProvider` 注入该语言字典；`t()` = `dict[s] ?? s`，**缺译文静默回退英文，永不开天窗**。
3. 工具页由 `tool-page-body.tsx` 按 slug 走 **97 条 `slug === "..."` 条件链**渲染对应组件；95 个组件全部顶层静态 import。
4. 重型能力按需加载：`xlsx` / `pdfjs-dist` / `mermaid` / `tesseract.js` 走动态 import 拆独立 chunk；**8 个视频工具的 ffmpeg.wasm 走运行时 unpkg CDN**（约 25 MB，首次约 7 秒）。
5. `AdUnit` 在客户端 `push({})`，但 `data-ad-slot="auto"` 无法关联任何广告单元。

## 二、四套运行机制拆解

### 2.1 路由与静态生成

`(public)` 路由组 = 英文站（无前缀）；`[lang]` = 15 个语言站。两套并行完整路由树，无共享根布局。`[lang]` 下 8 个静态型页面全部用 `export { default } from "../(public)/..."` 一行复用英文组件，仅单独覆盖 metadata；复用成立的前提是组件内部统一走 `I18nText` / `I18nLink` / `useI18n()`。

`generateStaticParams` 出现在 13 个文件，把 15 语言 × 104 工具 / 6 博文全部枚举，静态导出下无运行时回退。7 个 redirect 工具生成 `noindex, follow` 的中转页，canonical 指向目标工具，不输出 hreflang。

**副作用**：被复用的英文组件里硬编码的 JSON-LD 英文 URL、硬编码 `href="/"` 面包屑，也被 15 个语言页一并继承。

### 2.2 i18n 三层注入

| 层 | 数据 | 读取方 | 缺失回退 |
|---|---|---|---|
| UI 字典 | `src/i18n/messages/<lang>.json`（305–307 key） | `I18nProvider` → `t()/tl()` | 英文原文 |
| 工具元信息 + SEO 正文 | `src/i18n/content/<lang>.json`（`meta` 104 + `overrides` 96 + `generic` 1） | `src/i18n/content.ts` 的 `getMeta/getContent` | 英文 `tools-data` / 该语言 generic 模板 |
| 博客 | `src/i18n/posts/<lang>.json`（6 slug） | `getPostI18n()` → `PostArticle` | 英文原文 |

三类 JSON 都是**构建期预生成并已提交的静态产物**，运行时不翻译。语言切换是写 `localStorage["tb-lang"]` 后整页跳转（非客户端路由）；该 key **只写不读**，偏好记忆实际不生效。RTL（ar）已正确输出 `dir="rtl"`。

hreflang 双向互指完整（17 条/页，含 `x-default` 指向英文首页），canonical 每页恰好 1 个且自指——**这两项没有硬伤**。

### 2.3 工具分发与浏览器执行

- **无中央映射表**：`tool-page-body.tsx:11-105` 顶层静态 import 95 个组件，`:215-311` 用 97 条条件表达式分发。97 个可见 slug 全部有归宿，无遗漏、无空白页。
- **三种形态**：① `SimpleTool` 通用文本壳（约 32 个工具，靠 `placeholder`+`hint` 约定 `,` / `|` 分隔的结构化输入）；② 专用交互组件（滑块、canvas、WebAudio、FileReader、BigInt 等）；③ 3 个 `EmbedFrame` iframe 嵌入本地单页应用（Pilko / Viral Video Studio / OpenReel）。
- **「不上传用户文件」基本成立**：`src/` 内无 `FormData`、无上传型 `fetch`。但**站点并非零外部请求**，详见 3.3。
- **埋点：无任何第一方用户行为采集**。无 GA4/GTM/百度统计/Clarity/Plausible/Sentry。localStorage 只存 `tb-theme`、`tb-lang`、提词器全文。

### 2.4 部署与工作区卫生

- 域名 `toolbox-hub.io` 经 `public/CNAME` 登记，HTTPS 生效，`.nojekyll` 保护 `_next/`。
- **仓库 sitemap 与线上长期三方不一致**：HEAD 提交版 = 888 URL / 8 hreflang / lastmod 10-26；工作区与 `out/` = 1776 URL / 17 hreflang / lastmod 11-01；线上 = 1776 URL / lastmod 10-27。CI 每次重新生成却从不提交，快照持续失真（`LASTMOD = new Date()` 导致生成非幂等）。
- `git status`：**1 个 M + 16 个 `??`**。其中 `public/` 下 3 个 1 字节测试文件（`_wtest.tmp`、`sitemap.xml.tmp`、`sitemap2.xml`）会被 `git add -A` 提交、并随 `out/` 发布到生产域名；13 个 `ci-*.log/.sh`、`build-run.log` 同样漏出 `.gitignore`（文件里含代理地址、RUN ID、仓库名）。`out/` 虽被 git 忽略，但通过 `publish_dir` 整体发布——「忽略 ≠ 不发布」是这里的盲区。

### 3.2 变现链条断点

| 环节 | 状态 | 证据 |
|---|---|---|
| 内容 → 自然搜索流量 | 未验证 | 无 GSC 导出数据；文档自认「50+ 日流量是最大的坎」 |
| 流量 → 收录 | 未衡量 | 无 GA4，GitHub Pages 不给站主日志 |
| 页面 → 广告展示 | **断** | `ad-unit.tsx:42` `data-ad-slot="auto"`；Auto ads 未开 |

即使立刻过审、立刻来流量，**第一环（广告填充）就是 0**。

### 3.4 隐私 / 合规核对

| 项 | 结论 |
|---|---|
| 5 个信任页 | 均存在且有实质内容，Footer 全站链接，语言页经字典翻译 |
| Google 站点验证 | 有，且**两套不同 token**并存（meta + HTML 文件），可能分属不同 GSC 属性 |
| CMP / 同意管理 | **无**（无 banner、无 `__tcfapi`、无 fundingchoices），但 `privacy/page.tsx:74,100-103` 宣称「Google 发布同意管理通知」「依赖同意处理广告」 |
| AdSense 脚本注入范围 | 隐私政策页、信任页、`noindex` 中转页**均加载**（仅 404 不加载）；一旦开 Auto ads，广告会自动出现在这些禁止位置 |
| 隐私政策未披露 | 提词器全文写入 `tb-teleprompter-text`（用户正文，政策只提「theme or timezone」）、全部第三方 CDN/API/iframe、自托管 178+ Google Fonts、数据控制者实体与管辖地、CCPA「Do Not Sell」 |
| 联系邮箱 | `hello@toolbox-hub.io` 为注册商邮件转发 MX，无法验证收件箱有人查收 |
| `.io` + GitHub Pages | 无 ICP 备案；项目定位海外受众，但站点含 zh / zh-TW 两个中文版本，与广告主市场错配 |

### 3.5 机翻内容与规模化风险

`PUBLISHED_LANGS` 现含全部 16 语言、`isPublished()` 恒为 `true`，所有 `noindex` 分支与「Soon」标记均为死代码。15 × 111 ≈ **1665 个机翻页全部 `index, follow` 开放收录**，且 sitemap 全量列出。叠加部分语言 content 仍有英文残留（es 71%、pt 70%、pl 81%），构成 AdSense「Low Value Content / 规模化自动生成内容」与 SEO 权重稀释风险——项目文档自己也把 Low Value Content 列为拒审首因。

## 五、建议：按这个顺序做

> 原则：**先修「钱能不能到」和「会不会被封」，再修「能不能看见」，最后修「好不好用」。** 每步给出推荐结论，不列一堆让你自己选。

### 第 1 步 · 止血（本周，优先做，改动都很小）

1. **删掉 `public/` 三个 1 字节临时文件，`.gitignore` 补 `*.tmp` 和 `ci-*.log`/`ci-*.sh` 规则。** 理由：这是唯一一个「什么都不做、下次 push 就会自动出事」的问题。
2. **修广告填充**：推荐**从 AdSense 后台建真实广告单元，把 `data-ad-slot` 换成数字 ID**；如果账号尚未过审/不想维护 4 个 slot，则先移除手动广告位、只保留脚本，等过审后开 Auto ads。理由：`auto` 不填任何广告，改这个才有收入可能。注意开 Auto ads 前必须先做第 3 条。
3. **把 `adsbygoogle.js` 从隐私政策页、信任页、`noindex` 中转页排除**（按路径条件注入）。理由：Auto ads 一旦开启会在这些禁止位置自动插广告，属政策违规。
4. **加 CMP / 同意管理**（Google 认证的 Funding Choices 或等效方案），或至少对 EEA 流量在取得同意前不加载个性化广告。理由：现在无 CMP 却在隐私页宣称有，是 GDPR 与 Google 欧盟同意政策的双重硬伤。
5. **改「零上传/纯本地」文案**：把「never leave your device」改成准确表述（文件不上传；部分工具首次使用需从 CDN 加载运行引擎；本页含第三方广告），并修正 `embed-frame.tsx:146` 与「MIT License」。理由：这是 AdSense 最容易判「误导性内容」的一条，改文案成本极低。

### 第 2 步 · 让多语言 SEO 不白做（第 2 周）

6. **把 `getMeta(lang, slug)` 传给 `ToolPageContent`**（替换 `meta={tool}`），修 H1/副标题。理由：`getMeta` 已经算好了，只差传参，一处改动修 1455 页。
7. **博客语言页 `generateMetadata` 改用 `getPostI18n(lang, slug)` 而非 `st()`**；**`/<lang>/tools/` 去掉把工具数编进翻译 key**（改成模板插值）。理由：修 90 + 15 页的英文 SERP 标题，同时消除「每加一个工具 15 语言译文全失效」的定时炸弹。
8. **修 `tl("About the {title}", {title:""})` 的空插值**，并补齐语言页页面级 JSON-LD 的 URL/内容语言感知。理由：1552 页正文结构残缺。
9. **装 GA4 + 从 GSC 导出「网页」报告 CSV**。理由：没有这两个数字，第 1 步之后所有优化都是盲测；这也是 AdSense 审核「50+ 日流量」的前置判断依据。

### 第 3 步 · 决策项（第 3–4 周，需要先拍板）

10. **机翻语言是否继续全量开放收录**：推荐**先对译文覆盖率不足的语言（es/pt/pl 的 content 约 70–81%）保持 `index`，但把 15 语言×111 页的 hreflang 与 sitemap 暂时收敛到译文质量达标的语言**，其余设 `noindex` 直到补齐。理由：`PUBLISHED_LANGS` 机制本来就写好了，现在恒真等于白写；规模化机翻是 Low Value Content 拒审的直接靶子。
11. **CI 治理**：把 `--langs pl,vi` 改成全量或明确的语言清单、回写目录补 `src/i18n/posts`、去掉重复 sitemap 生成、给 `find` 清理加断言、加 paths 过滤。理由：现在 CI 每次只翻 2 语言，博客译文变更永远回写不进仓库。
12. **核实 OpenReel / Pilko 的再分发授权**，补 LICENSE 与归属说明；若无法确认，下架这两个嵌入工具。理由：完整第三方产品 + 混合许可 + 内置多个付费 API 端点，是版权与数据外发的双重隐患。

### 第 4 步 · 代码质量（有余力再做）

13. `tool-page-body.tsx` 把 97 条条件链改成对象映射 + `next/dynamic` 按 slug 懒加载；`header.tsx` 的全量 CONTENT 改为按语言注入。理由：主 chunk 4.6 MB、全站 JS 14 MB，首屏与 LCP 有明确优化空间。
14. 重写 4 个假/坏工具（`text-case-converter`、`youtube-thumbnail`、`favicon-generator`、`password-strength`），给 `SimpleTool` 加 try/catch 与 `htmlFor`。理由：功能正确性是留存与 AdSense 质量信号的基础。
15. 更新 `README.md`、删除 `schema.ts` 死代码、把语言清单收敛到单一数据源。理由：降低后续维护踩坑概率。

### 明确建议「现在不要做」的

- **不要再加新工具、不要再补翻译**（9 语言已于 10-28 全部上线，线上 `/ja/` 实测全日语正常）：当前瓶颈不在内容数量，在广告填充与合规。
- **不要为了国内可达性迁站或双线部署**：项目定位海外 AdSense 市场，GitHub Pages 是正确选择；中文语言版本反而是流量与广告主市场错配，优先级最低。
- **不要跑本地 `npm run build` 后直接 `git add -A`**：safe-delete 拦截器会留陈旧 `.next/out` 产物，且会连带触发一次 11–14 分钟的非预期生产部署。推送后交给 CI 构建即可。
