## 二、逐项技术调研

### 2.1 技术栈与架构（健康）

- Next.js **16.2.7** + React 19.2 + Tailwind CSS 4 + TypeScript 5
- `output: "export"` → 纯静态导出，天然适合静态托管
- `trailingSlash: true` → 与 sitemap/canonical 的 `/tools/xxx/` 结尾风格一致
- **100 个工具**，9 个分类：Developer 24 / Text 17 / Utility 13 / Design 10 / Calculator 10 / Web 8 / Converter 8 / Math 6 / Image 4（原 4 个 Video 工具均为伪造功能，已下架）
- 依赖极少（`lucide-react` + `qrcode`），**零后端、零数据库、零 API 成本** — 这是这个模式最大的优势，不要破坏它
- `next.config.ts` 干净，没有 basePath 污染 ✅

### 2.2 致命问题 1：canonical 全部指向首页

`src/app/layout.tsx` 里写了：

```ts
alternates: { canonical: "/" },
```

这是根 layout 的**全局** metadata，`src/app/tools/[slug]/page.tsx` 的 `generateMetadata` 没有覆盖它。实测构建产物：

```
json-formatter:      rel="canonical" href="https://toolbox-hub.io/"
qr-code-generator:   rel="canonical" href="https://toolbox-hub.io/"
password-generator:  rel="canonical" href="https://toolbox-hub.io/"
image-compressor:    rel="canonical" href="https://toolbox-hub.io/"
```

**后果**：105 个工具页在 Google 眼里全是首页的重复副本。canonical 是最强的合并信号，Google 会**主动不索引**这 105 个页面。SEO 直接归零 —— 工具站 100% 靠长尾词的长尾页面拿流量，这一刀等于把整个项目的商业模式砍掉。

**修复**（已实施）：删掉根 layout 的全局 canonical，改为每个工具页 `alternates: { canonical: '/tools/<slug>/' }`。

### 2.3 致命问题 2：线上站点实际不可用

DNS 已正确指向 GitHub Pages 的四个 A 记录（185.199.108-111.153），但：

- `gh api repos/.../pages` 返回 `cname: null` — **GitHub 侧从未登记这个自定义域名**
- 因此访问 toolbox-hub.io 时 GitHub 回 `Site not found · GitHub Pages`（502）
- `huajianlaojiu.github.io/toolbox-hub/` 返回 404

而且 `gh-pages` 分支里的构建产物是**老的**（15 个工具，资源路径带 `/toolbox-hub/` 前缀，是按子路径部署做的）。用自定义域名跑的话，这些 `/toolbox-hub/_next/...` 路径**全部 404**，页面会白屏。

**修复**（已实施）：
- `gh api -X PUT repos/.../pages -f cname=toolbox-hub.io` → 已登记成功
- `build_type` 改为 `workflow`，改用 Actions 部署（弃用 gh-pages 手工分支）
- 新增 `.github/workflows/deploy.yml`：checkout → npm ci → 生成 sitemap → build → 校验产物 → upload-pages-artifact → deploy-pages
- 静态资源走根路径（`/_next/...`），匹配自定义域名

### 2.4 致命问题 3：内容厚度不够，AdSense 必被拒

工具页正文实测（剔除 script/style 后）：

| 页面 | 正文词数 | 实际内容 |
|---|---|---|
| json-formatter | 59 | 标题 + 输入框 + 一句 "All processing happens in your browser" |
| qr-code-generator | 69 | 同上 |
| image-compressor | 70 | 同上 |

Google AdSense 拒审的首要理由就是 **Low Value Content**。2026 年公开案例显示，纯工具页 + 一句描述的站点被反复拒（copyfont.com 连续两次被拒；多个站点在补 FAQ/示例/信任页后才过）。

更关键的是：**这类站点即使过审，Google 也不会给流量**——因为工具页没有文字，Google 不知道该把它排到哪个查询上。

**修复**（已实施）：新增 `src/lib/tool-content.ts` 内容层
- 每个工具有独立的 `intro`（工具是什么 + 解决什么问题 + 何时用）、`howTo`（3 步）、`faq`（3–4 条问答）、`tips`
- 8 个核心工具（JSON / Base64 / QR / 密码 / 图片压缩 / 时间戳 / 字数 / 文件大小）已写成**手写的深度内容**，不是模板套壳
- 其余 97 个工具先走通用模板（每页文案随工具名/描述变化，不是完全相同的复制），后续逐个补深度
- 工具页新增渲染：About / How to use / Tips / FAQ 四个区块 + 工具页内嵌广告位

### 2.5 缺信任页（AdSense 硬性要求）

AdSense 审核会硬性检查 About / Contact / Privacy Policy / Terms / Disclaimer 五个页面是否可访问、是否有真实邮箱、隐私政策是否提及 cookie 与广告厂商。

**修复**（已实施）：新增 5 个页面
- `/about/` — 团队说明 + 运作方式 + 财务来源（广告）+ 编辑方针
- `/contact/` — 真实邮箱 hello@toolbox-hub.io + Bug 报告格式说明
- `/privacy/` — GDPR/CCPA 结构，含 Google AdSense cookie 披露 + opt-out 链接（AdSense 审核关键词全覆盖）
- `/terms/` — 使用条款 + 责任限制 + 知识产权
- `/disclaimer/` — 医疗/金融/加密工具专项免责声明

footer 已全部挂上链接。

### 2.6 结构化数据（schema.ts 是死代码）

`src/lib/schema.ts` 写好了 `generateWebApplicationSchema` / `generateToolSchema`，但**全项目没有任何地方 import 它**。而且里面的 URL 还指向 `toolbox-hub.vercel.app`（一个被其他人占用的域名，实测返回韩文站点「도구상자」）。

**修复**（已实施）：
- 根 layout 注入 `WebSite` + `FAQPage` JSON-LD
- 每个工具页注入 `@graph`：SoftwareApplication + HowTo（带 step）+ FAQPage
- schema.ts 里的 URL 统一改成 `https://toolbox-hub.io`

### 2.7 5 个假工具（高风险，建议尽快处理）

| slug | 实际行为 |
|---|---|
| `tiktok-downloader` | 只返回一段文字，告诉你去用 snaptik.app |
| `instagram-downloader` | 同上 |
| `youtube-shorts-downloader` | 同上 |
| `video-watermark-remover` | 只返回一段攻略文本 |
| `ip-lookup` | 只回显 navigator.userAgent，不是 IP 查询 |

这些页面**标题承诺的功能和实际能力不符**。后果：
- 用户跳出率极高 → 跳出率是 AdSense 的质量信号
- Google 判定"低价值/误导" → 拒审
- 若真的接第三方 API 抓取视频，还有平台条款与版权风险

**建议**：接真后端做，或直接下架（`tools-data.ts` 删 slug + sitemap 自动同步 + 页面上线）。别留着占位。

### 2.8 其他工程细节

- `src/app/tools/[slug]/page.tsx` 里有一段**重复的 JSX 块**（第 223 行）：`password-strength` / `html-preview` / `json-validator` / `image-resizer` / `unicode-converter` / `url-extractor` / `phone-formatter` / `text-stats` 这 8 个工具被渲染了**两遍**。页面上会出现两个相同输入框。
- `src/components/tool-page-client.tsx` 是死代码（页面没用它），且它的 `toolComponents` 只映射了 18 个工具。
- `all-tools.json` / `tool-defs.json` 是早期规划产物，与 `tools-data.ts` 不同步，没有被代码引用 → 建议删除或加注释标注为历史文件。
- 页面语言是英文 `<html lang="en">`，面向海外 AdSense 市场 —— **这是对的，不要改中文**。中文市场另开站。
- `header.tsx` 的搜索只做 `includes` 匹配，无拼写容错；可后置优化。

### 3.2 副线（第二优先级，流量起来后做）

1. **Affiliate**：工具页底部挂相关 SaaS 推荐（开发者工具受众 → JetBrains、GitHub Copilot、DigitalOcean、Namecheap）。开发者工具类 RPM 本来就低，affiliate 是补口子的正解。
2. **一次性付费去广告 / Pro**：等日活稳定后，用 Stripe/Paddle（**注意：PayPal 你刚踩过坑，Stripe 对个人主体更友好**）卖 "Ad-free" 一次性解锁。静态站没有后端，需要接 Stripe Checkout + 静态会员校验，或用 Cloudflare Workers 做轻量校验。
3. **API 付费**：给需要批量处理的场景（批量图片压缩、批量 Base64）。这需要后端，是从"纯静态"转向"有服务"的关键节点。

### 3.3 现实预期校准（重要，别被那份调研报告带偏）

项目里 `C:\Users\huaji\Documents\聚合工具网站\调研分析报告.md` 那份 6 月的报告给的数据偏乐观（"100 个工具 → 90K PV/月 → $450/月"）。真实情况：

- 工具站的流量**几乎全部来自 Google 长尾词**，而 Google 沙盒期是 **3–6 个月**，不是 3 个月
- 你的 105 个工具里，**竞争度最低的（Developer / Math / Converter）搜索量也最小**；真正高流量的（PDF、图片、AI、视频）竞争度极高
- 真正的护城河是**内容深度 + 域名权重 + 外链**，不是工具数量。105 个"薄工具 + 薄文案"的站，Google 不会给排名

**修正后的收入模型（保守）：**

| 阶段 | 时间 | 月 PV | RPM | 月收入 |
|---|---|---|---|---|
| 上线+过审 | 0–3 月 | 500–3K | $3–6 | $5–30 |
| 沙盒结束 | 3–6 月 | 3K–15K | $4–8 | $50–300 |
| 长尾起量 | 6–12 月 | 15K–50K | $5–10 | $250–1,500 |
| 内容/外链到位 | 12–24 月 | 50K–200K | $6–12 | $1K–4K |

**一句话：前 6 个月几乎零收入，这是这个模式的常态，不是失败。** 判断项目成败的 KPI 是第 6 个月的自然搜索流量和收录量，不是第一个月的美元。

## 五、部署与国内可达性说明

**这个站的受众是海外（AdSense + Google SEO + 英文），所以 GitHub Pages 是正确选择，不需要为大陆可达性做额外投入。** 但要清楚：

- GitHub Pages 在大陆访问慢/不稳 —— **对本项目无影响**（用户不在大陆搜索）
- **不要**为此迁 Cloudflare Pages（GFW 精准封堵已核实）
- 如果未来要给国内用户分发链接，优先腾讯云 CloudBase 静态托管（国内最快、免费版不扣费）或已备案的 wenankuai.com 自有服务器

如果要做**双线部署**（海外走 GitHub Pages + 国内走 CloudBase），输出目录是同一个 `out/`，加一个 CloudBase deploy 步骤即可，不冲突。
