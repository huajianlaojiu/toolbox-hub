## 三、发现并修复的问题

### 首页完全没有 canonical 标签

`src/app/layout.tsx` 的 `metadata` 只定义了 `metadataBase`，没有 `alternates.canonical`；
而 `tools/[slug]`、`blog/[slug]`、`blog` 各自都声明了自指 canonical，所以**只有 `/` 这一页漏了**。

影响：首页是权重最高的页面，缺 canonical 会让 Google 在
`https://toolbox-hub.io`、`https://toolbox-hub.io/`、`http://` 等变体之间自行选择，
也可能与 `index.html` 形式产生重复。

修复：layout metadata 增加 `alternates: { canonical: "/" }`。
子页自带的 `alternates` 优先级更高，不受影响（已验证 `/tools/json-formatter/` 仍自指）。

- commit：`94daa37`
- 线上验证：首页返回 `<link rel="canonical" href="https://toolbox-hub.io/"/>`

## 四、为什么 Google 收录数拿不到（重要）

1. **Google 搜索结果页现在是纯 JS 壳**：`curl` 拿到的是 92KB 的空壳 HTML，0 条结果，
   必须执行 JS 才有数据，而 `site:` 查询本身也不再稳定返回准确计数。
2. **Bing 的 `site:` 操作符对该域名被忽略**：返回 60 条结果全部是无关站点
   （にゃんこ大戦争、協会けんぽ、NBA 等），说明 Bing 索引里 toolboxt-hub.io 基本为空，
   这不能代表 Google。
3. **GSC API 需要 OAuth 凭据**，当前环境没有。

→ 唯一可靠路径是从 GSC 后台导出「网页」报告的 CSV，再做本地分析。

## 五、需要你做的：导出 GSC 数据（约 2 分钟）

1. 打开 https://search.google.com/search-console
2. 左侧 **索引编制 → 网页**（Pages）
3. 右上角 **导出 → 下载 CSV**（若提示只导出前 1000 行，直接确认，我们只有 113 页）
4. 同一个页面上方，**已编入索引 / 未编入索引** 的两块数字截图给我
5. 左侧 **站点地图**（Sitemaps）页面：确认 `sitemap.xml` 的「已发现的网页」数字
6. 把 CSV 文件路径告诉我（放到 `D:\AI应用\toolbox-hub\` 下即可），我做本地分析

分析内容：实际被 Google 收录的 URL 清单、未收录的原因分类
（已抓取未编入索引 / 已发现未抓取 / 被 robots 屏蔽 / 已提交但未选中规范网址）、
以及针对每类原因的处理动作。
