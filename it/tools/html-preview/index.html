About the HTML Preview

The HTML Preview renders a fragment of HTML live so you can see what it produces without saving a file and opening it. It is meant for short snippets: an email template, a component's markup, a snippet from a content management system, or anything else you want to eyeball before pasting it somewhere. Switching between edit and preview is instant, which makes it a fast loop for tweaking markup.

Where people use the HTML Preview

  • Checking an email template fragment before sending a test.
  • Previewing markup pasted out of a content management system.
  • Sanity-checking a snippet before pasting it into a pull request.
  • Testing whether a table or a list renders the way you expect.

How to use the HTML Preview

  1. 1

    Paste your markup

    Type or paste an HTML fragment into the editor. A full document or just a snippet both work.

  2. 2

    Switch to preview

    Press Preview to render it. The markup is drawn into the page as it would appear in a browser.

  3. 3

    Switch back and adjust

    Press Edit to return to the markup. Changes are kept, so you can iterate.

  4. 4

    Copy it out when you are happy

    Select the markup in the editor and copy it into your project.

Tips and best practices

  • Add inline styles if your fragment depends on a stylesheet that is not here.
  • A clean render is not proof of valid markup; browsers paper over errors.
  • Keep the preview in mind for snippets, not for whole pages with script behaviour.

Frequently asked questions

Does it support CSS and JavaScript?

Style tags and inline styles render. Scripts are rendered as markup, but this is a preview of a fragment, so treat script behaviour as unreliable.

Why does my snippet look different from my site?

Because the surrounding stylesheet is missing. A fragment inherits nothing here, so anything that relies on your site's CSS will look unstyled.

Can I load external images or fonts?

Yes, if they are publicly reachable, though the surrounding page's own rules still will not apply.

Is the markup uploaded?

No. Rendering happens in your browser, so unpublished templates and internal content stay on your device.

Does it validate the HTML?

No. It renders what you give it. A browser will silently fix some mistakes, so a clean render does not prove the markup is valid.
